# SeeSay

Приложение SeeSay для смарт-очков. Оно описывает сцену перед пользователем и читает текст с кадра. Ответ анализа озвучивается через TTS.

Экраны: `/` и `/home` (главный), `/settings`, `/history`. Ориентация — портрет.

## Запуск

Нужны Flutter stable и Android SDK (minSdk 26).

```text
flutter pub get
flutter run
```

Проверка:

```text
flutter analyze
flutter test
```

Сборка:

```text
flutter build apk --debug
```

## Конфигурация

Файл `.env` в корне проекта подключается как asset. Те же ключи можно передать через `--dart-define`: они перекрывают файл.

| Ключ | По умолчанию | Смысл |
| --- | --- | --- |
| `API_BASE_URL` | `http://10.0.2.2:8000` | Базовый URL FastAPI. `10.0.2.2` — хост-машина с эмулятора. |
| `USE_MOCK_GLASSES` | `true` | Имитация очков без BLE. |
| `USE_MOCK_API` | `true` | Локальные ответы вместо `/api/v1/analyze-frame` и `/api/v1/read-text`. |
| `USE_MOCK_CAMERA` | `false` | Снимок без камеры телефона. |
| `USE_MOCK_TTS` | `false` | Озвучивание без Android TTS. |

На платформе, отличной от Android, очки, камера и TTS принудительно работают в режиме имитации.

Реальные очки и backend:

```text
USE_MOCK_GLASSES=false
USE_MOCK_API=false
USE_MOCK_CAMERA=false
USE_MOCK_TTS=false
```

Разрешения запрашиваются в момент использования: Bluetooth и уведомления при подключении, камера при снимке, геолокация необязательна при анализе.

## Демонстрация без очков

1. Запуск. Статус подключения виден на карточке, без стартовой фразы.
2. Нажать карточку очков, чтобы подключить или отключить их.
3. «Что вокруг» делает снимок и отправляет его на анализ.
4. В режиме имитации API ответ: «Перед вами вход в аптеку. Дверь справа. Перед дверью две ступени.» Его произносит TTS.
5. «Повтор» произносит тот же текст ещё раз.
6. Промежуточные фразы действий («Делаю снимок», «Очки подключены», названия кнопок) не озвучиваются. Ошибки сети и Bluetooth по-прежнему произносятся.

В настройках, пока включена имитация очков, есть кнопка имитации кнопки очков. Она отправляет BLE-пакет снимка.

Без сети приложение говорит: «Нет подключения к интернету. Попробуйте ещё раз.» Если Bluetooth выключен: «Bluetooth недоступен.»

## Протокол Native ↔ Flutter

Каналы заданы в `lib/core/platform/glasses_protocol.dart`.

- MethodChannel: `com.example.seesay/glasses`
- EventChannel: `com.example.seesay/glasses_events`

Команды Flutter → Kotlin. Аргументы — map, если не указано иное. Успех — `true` или `null`. Ошибка речи: code `speech`.

| Метод | Аргументы | Поведение |
| --- | --- | --- |
| `connectGlasses` | `deviceAddress` (String?) | Запускает foreground service и BLE. |
| `disconnectGlasses` | — | Останавливает сервис. |
| `startCapture` | — | Шлёт событие `MEDIA_PLAY_PAUSE` (снимок с очков). |
| `stopCapture` | — | Успех без действия: один JPEG, не поток. |
| `speak` | `text`, `rate`, `language` | Android TTS, `USAGE_MEDIA`. Result завершается по окончании фразы. |
| `stopSpeaking` | — | Останавливает текущую фразу. |
| `setSpeechRate` | `rate` | Скорость TTS, обычно 0.5–2. |
| `setLanguage` | `language` | Например `ru-RU` или `en-US`. |
| `getConnectionState` | — | Строка: `disconnected`, `connecting`, `connected`, `error`. |
| `isBluetoothEnabled` | — | `bool`. |
| `haptic` | `kind` | `tap`, `success`, `error`, `connection`, `capture`. |
| `beep` | `kind` | Тот же набор. |

События Kotlin → Flutter. Каждое сообщение — map с полем `event`.

| `event` | Поля |
| --- | --- |
| `bleConnectionChanged` | `state`; необязательно `message`, `deviceAddress` |
| `blePacketReceived` | `bytes`: список int 0–255 |
| `mediaButtonEvent` | `action`: `MEDIA_PLAY_PAUSE`, `VOLUME_UP`, `VOLUME_DOWN` |
| `batteryChanged` | `level`: int |

`MEDIA_PLAY_PAUSE`, `HEADSETHOOK`, `PLAY` и `PAUSE` приходят как `MEDIA_PLAY_PAUSE` и запускают анализ сцены. `VOLUME_UP` и `VOLUME_DOWN` только логируются, громкость остаётся системной. Повторный снимок с очков и с кнопки медиа глушится на 800 мс.

BLE: сервис `0000fa00-0000-1000-8000-00805f9b34fb`, notify `0000ea01-0000-1000-8000-00805f9b34fb`, CCCD `00002902-0000-1000-8000-00805f9b34fb` (запись `0x0100`). Пакет без заголовка `ED 40` отбрасывается. Если заголовок верный, а шаблон неизвестен, тип — unknown. Берётся самое раннее совпадение.

| Шаблон | Смысл |
| --- | --- |
| `12 0F 01` | Кнопка фото |
| `12 0D 01 01` | Съёмка началась |
| `12 0D 04 01` | Двойное касание: повторить ответ |
| `12 0D 02 02` | Инициализация видео |
| `12 0D 02 01` | Запись |
| `12 0D 00 00` | Покой |

Foreground service типа `connectedDevice`, канал уведомлений `aimb_s2_glasses`. Тексты: «SeeSay: очки подключены» и «SeeSay: выполняется подключение». Это служебное уведомление Android для foreground service. Отдельные уведомления о событиях очков не создаются.

Дополнительные команды того же MethodChannel:

| Метод | Аргументы | Поведение |
| --- | --- | --- |
| `startBackgroundMonitoring` | — | Запускает сервис и, в демо-режиме, генератор событий. |
| `stopBackgroundMonitoring` | — | Останавливает генератор. Сервис остаётся, пока очки подключены. |
| `getBackgroundMonitoringStatus` | — | `bool` из локального хранилища. |
| `enableMockMode` / `disableMockMode` | — | Включает или выключает имитацию. |
| `triggerMockEvent` | `type` | Одно событие, только если мониторинг и демо-режим включены. |
| `getPendingGlassesEvents` | — | Неподтверждённые события. |
| `getRecentGlassesEvents` | — | Последние события, не больше 100. |
| `acknowledgeGlassesEvent` | `eventId` | Отмечает событие обработанным. |

Живые события приходят в EventChannel как `event: glassesEvent`. Поле `source`: `mock`, `ble` или `backend`. Событие сначала записывается в SharedPreferences `aimb_glasses_events`, и только потом отправляется во Flutter. Если движок Flutter отсоединён, сервис продолжает работу, а речь для текста, сцены, подключения и ошибки устройства произносит Android TTS.

## Демо-режим и фоновый мониторинг

1. Откройте «Профиль».
2. Включите «Демонстрационный режим». На главной виден тот же индикатор. Значения имитации не показываются как данные с физических очков.
3. Включите «Фоновый мониторинг». На Android это запускает `GlassesForegroundService`, пока приложение на экране.
4. Нажмите чип типа события, например «Текст». Событие сохраняется и появляется в «Последние события» и в истории AI-помощника, если это распознанный текст или сцена.
5. Интервал автоматических событий — 30 секунд. Генератор молчит, пока мониторинг или демо-режим выключены.

Осмотр журнала: `adb logcat -s GlassesForegroundService MockGlassesEventSource`. Хранилище событий — класс `GlassesEventStore`.

Ограничение производителей: агрессивные режимы батареи могут остановить foreground service, даже если Android его разрешает. Приложение не перезапускает сервис из фона само. После force-stop пакет не генерирует события, пока пользователь снова не откроет приложение и не включит мониторинг.

## Ручная проверка фона

Идентификатор приложения: `com.example.seesay`.

```text
adb shell dumpsys activity services com.example.seesay
adb logcat -s GlassesForegroundService MockGlassesEventSource
adb shell am force-stop com.example.seesay
```

Force-stop используйте только в тесте D.

### Тест A — приложение на экране

1. Установите и откройте приложение.
2. Включите демо-режим и фоновый мониторинг.
3. Запустите тестовое событие «Текст».
4. Проверьте, что оно есть в AI-помощнике или в последних событиях.
5. При включённой речи прозвучит «На табличке написано: …».

### Тест B — приложение в фоне

1. Запустите мониторинг.
2. Нажмите Home.
3. Дождитесь события или вызовите его, пока сервис жив.
4. В logcat должна быть обработка сервисом.
5. Откройте приложение снова. Событие одно, без дубля.
6. Отдельного уведомления о событии нет.

### Тест C — Activity уничтожена

1. Запустите мониторинг и уйдите в фон.
2. Уничтожьте Activity, не останавливая пакет целиком.
3. Пока Android держит сервис, события пишутся в хранилище.
4. Запустите приложение снова и проверьте синхронизацию.

### Тест D — force-stop

1. Запустите мониторинг.
2. Выполните `adb shell am force-stop com.example.seesay`.
3. Локальные события после этого прекращаются.
4. Откройте приложение. Состояние сервиса восстанавливается без падения. События сами не продолжаются.
